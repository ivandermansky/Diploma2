**Обзор**
Набор автоматизированных тестов для проверки API веб‑приложения. 
Тесты покрывают функциональность работы с пользователями и заказами, включая:

создание, аутентификацию и валидацию пользователей;
создание и получение заказов;
обработку ошибок и проверку безопасности.

Текущий статус: обнаружен баг — сервер позволяет создавать заказы без авторизации (тест shouldNotCreateOrderWithoutAuth падает).

Технологии и инструменты:
Java 11+ — язык программирования;
JUnit 4 — фреймворк для тестирования;
REST Assured — тестирование REST‑API;
Allure — генерация отчётов о тестировании;
Maven — управление зависимостями и сборка.

Описываемые API‑эндпоинты
Эндпоинты пользователей
POST /api/auth/register — создание пользователя;

POST /api/auth/login — аутентификация пользователя;

DELETE /api/auth/user — удаление пользователя.

Эндпоинты заказов
POST /api/orders — создание заказа (с авторизацией/без);

GET /api/orders — получение списка заказов (с авторизацией/без).

Описание тестов
Тесты заказов (OrderTests)
shouldCreateOrderWithAuth() — создание заказа авторизованным пользователем:

создаёт заказ с тестовыми ингредиентами;

проверяет статус 200 OK и success: true.

shouldNotCreateOrderWithoutAuth() — создание заказа без авторизации:

ожидаемый результат: статус 401 Unauthorized, success: false;

текущий баг: сервер возвращает 200 и создаёт заказ.

shouldNotCreateOrderWithoutIngredients() — заказ без ингредиентов:

проверяет статус 400 Bad Request и сообщение об ошибке.

shouldNotCreateOrderWithInvalidIngredient() — заказ с неверным ID ингредиента:

проверяет статус 500 Internal Server Error.

shouldGetOrdersWithAuth() — получение заказов авторизованным пользователем:

сначала создаёт заказ, затем получает список;

проверяет статус 200 OK и success: true.

shouldNotGetOrdersWithoutAuth() — получение заказов без авторизации:

проверяет статус 401 Unauthorized и сообщение «You should be authorised».

Тесты пользователей
Позитивные сценарии
CreateUserPositiveTest.shouldCreateUserSuccessfully() — успешное создание пользователя с уникальными данными;

UserLoginPositiveTest.shouldLoginSuccessfully() — успешный вход зарегистрированного пользователя.

Негативные сценарии
CreateUserNegativeTest.shouldNotCreateDuplicateUser() — предотвращение дублирования аккаунта;

CreateUserWithMissingFields — валидация обязательных полей (email, password, name);

UserLoginNegativeTest — обработка ошибок при входе с неполными данными.

Принципы тестирования
Изоляция тестов: каждый тест создаёт и удаляет отдельного пользователя.

Тестовые данные:

уникальные email/пароль (генерируются GenerateUserData);

фиксированные ID ингредиентов для заказов.

Валидация ответов - для каждого запроса проверяется:

HTTP‑статус;
структура JSON‑ответа (success);
содержание сообщений об ошибках.

Параметризованные тесты: используются для проверки нескольких сценариев одним шаблоном (например, CreateUserWithMissingFields).


**Настройка и запуск

Предварительные требования**
Java 11;
Maven 3.6+;
доступ к тестируемому API.
Зависимости Maven

**Убедитесь, что в pom.xml присутствуют следующие зависимости:**

</dependencies>



**Текущие проблемы**
Баг в API: сервер позволяет создавать заказы без авторизации (shouldNotCreateOrderWithoutAuth падает). Ожидается статус 401, но возвращается 200.

Рекомендации: сообщить разработчикам для исправления бизнес‑логики авторизации.

**Рекомендации по разработке gри добавлении новых тестов:**

Используйте существующие модели данных (User, Order).
Применяйте параметризованные тесты для схожих сценариев.
Добавляйте аннотации Allure для улучшения читаемости отчётов.
Убедитесь, что тестовые данные корректно очищаются в @After.

**При отладке:**

проверяйте логи консоли для сообщений о статусе ответов;

убедитесь, что API доступно и возвращает ожидаемые данные;

при ошибках валидации сверяйте структуру запросов с документацией API.

Устранение неполадок
Проблема: тест падает из‑за недоступности API

проверьте доступность эндпоинтов;

убедитесь, что URL указан корректно (в ApiEndpoints.java).

Проблема: тесты не проходят из‑за изменений в API

обновите модели данных (User, Order);

скорректируйте валидацию ответов в тестах.

Проблема: ошибки аутентификации

проверьте генерацию тестовых данных (GenerateUserData);

убедитесь, что токен доступа извлекается корректно.
